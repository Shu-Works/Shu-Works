## 0. 全案に共通する「正直な制約評価」（最重要）

3案すべての土台。**ここを誤魔化すと自動化全体が砂上の楼閣になる**ので先に明記する。

| 工程 | 無人自動化の可否 | 正直な評価 |
| --- | --- | --- |
| ネタ決め | ✅ 可 | ChatGPT API で候補生成 → Notion 起票。問題なし |
| 脚本生成 | ✅ 可 | ChatGPT API。問題なし |
| 画像プロンプト生成 | ✅ 可 | ChatGPT API。問題なし |
| 承認依頼メール（A/B）作成 | ✅ 可 | Gmail 下書き生成まで自動。**送信＝人間** |
| 承認返信の解釈 | ✅ 可 | Gmail 受信トリガー＋本文1語パース |
| 投稿メタ（タイトル/説明/タグ）下書き | ✅ 可 | ChatGPT API |
| **画像生成（Google Flow）** | ❌ **無人不可** | **Google Flow は公開 API／無人自動化の手段が無い**。ブラウザ上の手作業が必須。一貫性の3点固定（キャラシート・画風ブロック・16:9）も人の目での採否判断が要る。→ **代替の画像生成API（後述）に置き換えない限り、ここは人手 or 半自動が上限** |
| 音声生成（ナレーション） | △ 条件付き可 | **ElevenLabs は API あり → 無人生成は技術的に可能**。ただし Make にネイティブ・モジュールが無いため **HTTP モジュール経由**で叩く。生成後の「言い直し・呼吸音カット」は Filmora 上の人手 |
| **動画編集（Filmora）** | ❌ **無人不可** | **Filmora はデスクトップ編集ソフトで API／無人実行が無い**。スライド化・字幕・ショート切り出しは人手が上限。→ **無人化したいなら Canva 等のAPI/プログラム生成可能なレンダラに置き換える**しかない |
| ショート切り出し | ❌ 無人不可（Filmora前提） | 同上。本編から人手で切る |
| YouTube 投稿 | ✅ 可（要 API 設定） | YouTube Data API で無人投稿は可能。ただし **API 申請・OAuth・クォータ管理**が必要 |
| 実績トラッキング | ✅ 可 | YouTube Analytics を定期取得 → Notion |

**結論**：Google Flow と Filmora を使う限り、**画像生成と動画編集は必ず人手が残る**。完全自動を目指すなら、この2工程を「API/プログラム制御できる別ツール」に置き換える投資判断が要る（＝案C）。各案はこの一線をどこで引くかの違いである。

## 0.5 CEO追記（2026-06-17）：Canva Bulk Create を「組み立てエンジン」に採用

社長提案を採用。**§0で「Filmoraは自動化の袋小路」と指摘した壁を、Canvaが塞ぐ。** Canva は本セッションに **API（MCP）が接続済み**で、`generate-design` / ブランドテンプレ＋`get-brand-template-dataset`（Bulk Create 相当）/ `upload-asset-from-url`（Driveの素材投入）/ `export-design`（書き出し）をプログラムから叩ける。Filmora に無い「無人化の本線」がCanvaにはある。→ **案B・案Cの組み立て工程は Filmora ではなく Canva を標準にする。**

### ワークフロー（社長案）
1. ChatGPTが各シーンの「字幕テキスト」をCSVで出力（10行）。
2. Canva にブランドテンプレ（16:9・テキスト位置・トランジション固定）を1つ作る。
3. **Bulk Create** でCSVを流し込み、全10ページのテキストを一括自動配置。
4. Drive の画像10枚を各ページに配置（`upload-asset-from-url`でAPI投入も可）。
5. ナレーション音声を配置 → 動画書き出し。

### 正直な制約（過剰約束しない）
- ✅ **テキスト＋画像の一括配置はBulk Createで自動化できる**。ここがFilmora手作業より速い。本命。
- △ **音声のページ同期は半自動が上限**。Bulk Createは音声を扱わない。各ページへの音声配置・尺合わせは人手 or 個別API操作が残る。
- △ **ナレーションの言い直し・呼吸音カット**は依然どこかで必要（ElevenLabs生成時に整える or 簡易音声編集を1パス）。Canvaは細かい音声トリムが弱い。
- ⚠️ **最終書き出しの音ズレ**だけは要検証。**ep001で1本だけ実測**してから標準化する（Real Artists Ship＝まず1本試す）。

### 制約評価表の更新
| 工程 | 旧（Filmora前提） | 新（Canva採用後） |
| --- | --- | --- |
| 動画組み立て（スライド化） | ❌ 無人不可 | ✅ **Bulk Create＋APIで自動化可**（音声同期のみ半自動） |
| ショート切り出し | ❌ 無人不可 | △ Canvaでリサイズ複製→半自動 |
| 画像生成（Google Flow） | ❌ 無人不可 | ❌ 変わらず（画像生成API置換が案Cの宿題。Canva AI画像で巻き取れるかep001で試す） |

→ **これで案Cの最大の壁（編集の無人化）が現実的になった。** 残る壁は画像生成（Google Flow）だけ。

## 案A：半自動・最小（"文章だけ自動・今すぐ寄り"）

### コンセプト
**「文章工程（脚本・プロンプト・メタ・承認メール）だけを自動化し、絵作りは人が握る」**。一番壊れにくく、手動5本の延長で今すぐ始められる。当たりの型を探す検証期に最適。

### フロー図（🟢自動 ／ 🟡半自動 ／ 🔴人手）
```
🟢 ネタ供給（Make定期 → ChatGPTで候補 → Notion起票）
   ↓ status:ネタ確定
🟢 脚本＋画像プロンプト生成（ChatGPT → Drive保存 → Notion更新）
   ↓ status:プロンプト済
🟢 承認依頼Aドラフト生成（Gmail下書き）
🔴 社長：A-GO / A-NG を1語返信
🟢 返信解釈 → Notion遷移
   ↓ status:物語承認済
🔴 画像生成（Google Flow・手作業10枚）         ← 人手必須
🔴 音声生成（ElevenLabs・手 or 半自動）          ← 案Aでは人手
🔴 動画化＋ショート（Filmora・手作業）           ← 人手必須
   ↓（人がNotionで「動画生成済」に手更新）
🟢 承認依頼Bドラフト生成＋投稿メタ下書き＋Calendar空き枠提案（Gmail下書き）
🔴 社長：B-GO / B-NG を1語返信
🔴 YouTube投稿（人が手動アップロード）            ← 案Aでは人手
🟢 実績トラッキング（定期取得 → Notion）
```

### 自動化される工程／人手が残る工程
- **自動**：ネタ・脚本・プロンプト・承認A/Bメール下書き・返信解釈・Notion遷移・投稿メタ下書き・Calendar空き枠提案・実績取得
- **人手**：画像生成（Google Flow）／音声（ElevenLabs手動）／動画＋ショート（Filmora）／YouTube投稿の公開操作
- **承認2ゲート**：A・B とも Gmail 下書き自動＋1語返信。設計通り維持

### 使うツール
Make.com（S0〜S3, S5, S7 のみ）＋ Notion ＋ Google Drive ＋ Gmail ＋ Google Calendar ＋ ChatGPT API。**Canva/YouTube API は使わない**。

### 構築の手間・コスト・リスク
| 項目 | 評価 |
| --- | --- |
| 構築の手間 | **低**（Make シナリオは文章系の5本だけ。画像/編集/投稿のシナリオを作らない） |
| 月額コスト感 | **低**（Make 無料〜Coreプラン／ChatGPT API 従量・1本数十円／ElevenLabsは使う分だけ。月数千円規模） |
| 壊れやすさ | **低**（外部の不安定要素＝Google Flow/Filmora/YouTube API を自動フローに入れない＝壊れる箇所が少ない） |

### いつ採用すべきか
**今すぐ〜手動5本直後**。当たりテーマを探す検証段階。「文章の段取りと承認の往復」という一番面倒な事務だけを消し、絵作りの感覚は人が保持したい時期にちょうど良い。

### 社長の手作業（1本あたり）
- 承認A・B の判断＋1語返信：**約3〜5分**
- ＋画像生成8分＋音声3分＋動画化7分＋ショート5分＋投稿3分（＝制作実務）は**まだ人手**
- **社長/制作の実働合計：約30分前後**（うち社長の純粋な「判断」は3〜5分、残りは制作作業）

### コンセプト
**「音声を API で無人化し、画像は半自動（人は採否だけ）、投稿メタも自動下書きまで持っていく」**。文章だけでなく"重い素材作り"の一部まで自動化に寄せる中間案。検証で型が見えてきて、本数を増やしたい時期向け。

### フロー図（🟢自動 ／ 🟡半自動 ／ 🔴人手）
```
🟢 ネタ供給 → 🟢 脚本＋プロンプト生成
   ↓ status:プロンプト済
🟢 承認依頼Aドラフト → 🔴 社長A-GO/NG → 🟢 返信解釈
   ↓ status:物語承認済
🟢 音声生成（ElevenLabs API を Make HTTPで起動 → Drive保存 → Notion更新）  ← 無人化
🟡 画像生成（Google Flow：人が10枚生成、Driveに置く）                      ← 半自動
   ┗ 🟢 Make が Drive 投入を検知 → Notion「画像生成済」へ自動更新
🔴 動画化＋ショート（Filmora・手作業）                                     ← 人手必須
   ↓（人がNotionで「動画生成済」に手更新）
🟢 投稿メタ自動下書き（ChatGPTでタイトル/説明/タグ → Notion＆Drive）
🟢 承認依頼Bドラフト生成＋Calendar空き枠提案（Gmail下書き）

🟡 YouTube投稿（人が手動 or 半自動：メタは自動で揃え、公開操作のみ人）
🟢 実績トラッキング（定期取得 → Notion）→ 🟢 30本で上位分析（S8）
```

- **案Aから増える自動**：①音声生成（ElevenLabs API・無人）②画像のステータス自動更新（人は"絵を作って置く"だけ、ステータス管理から解放）③投稿メタの自動下書き④上位分析S8

- **半自動の定義**：「人が素材を作って Drive に置く → Make が検知して進行を進める」。人は判断と手作業に集中し、**進行管理の手入力はゼロ**になる

Make.com（S0〜S3, S5〜S8）＋ Notion ＋ Drive ＋ Gmail ＋ Calendar ＋ ChatGPT API ＋ **ElevenLabs API（HTTP）**。YouTube は半自動（メタ自動・公開人手）。Canva は任意。

| 項目 | 評価 |
| --- | --- |

**手動5本→案Aで段取りが固まった後、月10〜20本へ増やす段階**。音声生成という地味に時間を食う工程を消し、人を「絵の採否」と「編集」に集中させたい時。

### 社長の手作業（1本あたり）
- 承認A・B の判断＋1語返信：**約3〜5分**（変わらず）

## 案C：ほぼ全自動・量産（"当たり確定後の量産機"）

### コンセプト
**「Google Flow を API 制御可能な画像生成に、Filmora をプログラム生成可能なレンダラに置き換え、承認2ゲットだけ人間にして量産する」**。当たりの型が確定し、品質を固定して本数を稼ぐフェーズ専用。**要投資・要構築**。

### 重要な前提（正直に）
案Cは**現行ツール（Google Flow／Filmora）のままでは実現できない**。以下の置き換えが前提：
- **画像**：Google Flow → API 提供のある画像生成（例：OpenAI画像API等のプログラム制御可能なもの）。ただし**一貫性の3点固定（同一キャラの顔の連続性）はAPIだと崩れやすく、品質リスクが最大の課題**。当たり画風を1つに固定し、崩れたら自動リトライ＋閾値超えで人手フォールバックの設計が要る。
- **動画編集**：Filmora → **Canva API**（接続済み）または プログラムでスライド合成できるレンダラ。Ken Burnsズーム・字幕・OP/ED・BGMをテンプレ固定して機械合成。**Filmoraで作る微細な編集品質は一段落ちる**ことを許容する判断が要る。
- **投稿**：YouTube Data API（OAuth＋クォータ管理＋API審査）。

### フロー図（🟢自動 ／ 🟡半自動 ／ 🔴人手）
```
🟢 ネタ → 🟢 脚本＋プロンプト
🟢 承認依頼Aドラフト → 🔴 社長A-GO/NG（唯一の人手①）→ 🟢 返信解釈
   ↓ status:物語承認済
🟢 画像生成（画像生成API・自動10枚・崩れたら自動リトライ）
   ┗ 🟡 一貫性NG閾値超のみ人手フォールバック（例外時だけ）
🟢 音声生成（ElevenLabs API）
🟢 動画化（Canva API等でスライド合成＋字幕＋BGM・テンプレ固定）
🟢 ショート切り出し（同テンプレで9:16自動生成）
🟢 投稿メタ自動生成＋サムネ自動（Canva）
🟢 承認依頼Bドラフト＋Calendar枠 → 🔴 社長B-GO/NG（唯一の人手②）
🟢 YouTube API 自動投稿
🟢 実績トラッキング → 🟢 30本で上位分析 → 🟢 S0テーマ生成へ自動フィードバック
```

### 自動化される工程／人手が残る工程
- **自動**：ネタ〜投稿〜分析まで原則すべて。承認2ゲートの間が完全無人
- **人手**：**承認A・B の2回の1語返信だけ**（＋画像一貫性NG時の例外フォールバック）
- **承認2ゲート**：唯一残す人間判断。ここは絶対に外さない（フィクション明示・品質の最終責任）

### 使うツール
Make.com（全シナリオ S0〜S8）＋ Notion ＋ Drive ＋ Gmail ＋ Calendar ＋ ChatGPT API ＋ **画像生成API（要選定・Flow置換）** ＋ ElevenLabs API ＋ **Canva API（Filmora置換）** ＋ **YouTube Data API**。

### 構築の手間・コスト・リスク
| 項目 | 評価 |
| --- | --- |
| 構築の手間 | **高**（画像API選定＋一貫性担保ロジック＋Canvaレンダリング自動化＋YouTube API審査＋全エラーハンドリング。実装は数週間規模） |
| 月額コスト感 | **中〜高**（Make上位プラン＋画像API従量＋ElevenLabs＋Canva有料＋API運用。月 1.5〜4万円規模＋構築初期投資。**1件5万円超の支出が絡む場合は CEO/社長決裁が必要**） |
| 壊れやすさ | **高**（外部API4種が連鎖。1つ仕様変更で止まる。**画像の一貫性崩れ＝品質劣化が最大リスク**。無人で凡庸な動画を量産する危険＝CLAUDE.md §11/§18 に抵触しうる） |

### いつ採用すべきか
**当たりテーマ・当たり画風が完全に確定し、品質を固定したまま月30本以上を量産するフェーズ**。それ以前に組むと、固まっていない型を高速で大量生産する＝凡庸の量産になる（§11 One home run に反する）。**急いではいけない案**。

### 社長の手作業（1本あたり）
- 承認A・B の判断＋1語返信：**約3〜5分のみ**（制作実務は全消滅）
- **社長の実働合計：約3〜5分**（例外フォールバック発生本のみ＋数分）

## CEO（Jobs）への推奨：案A

**理由**：
1. CEO 方針＝「手動5本で当たりを掴んでから自動化」と完全に整合する。案Aは手動5本の**自然な延長**で、絵作りの感覚を人が握ったまま、面倒な事務（脚本段取り・承認往復・進行更新）だけを消す。
2. **壊れにくい**。不安定な外部要素（Google Flow/Filmora/YouTube API）を自動フローに入れないので、自動化が原因で止まる事故が起きない。Cash is oxygen の観点でも初期投資ゼロに近い。
3. §22 Real Artists Ship。完璧な全自動（案C）を最初から狙うのは、固まっていない型を高速量産する罠。**型が固まる前に量産機を作るのは凡庸の量産**（§11 違反）。
4. 案B・Cは「いつか効く」が、効くのは**型が固まった後**。今これを組むのは早すぎる。

**却下した選択肢**：案Cを「最初から」は明確に却下。当たりが確定していない段階で全自動を組むのは、§11 One home run と §18 品質の物差しに反する。案Bは検証中盤で再検討する価値はあるが、5本も出ていない今の着手は時期尚早。

## 段階移行ロードマップ（1本）

```
【現在】手動5本（manual-runbook.md）
   │  目的：当たりテーマ・型の体感。社長実働 約30分/本
   ▼
【Step1】案A 導入（5本完了直後〜）         ← 推奨スタート
   │  文章＋承認事務を自動化。絵作りは人手のまま
   │  社長：判断3〜5分＋制作30分/本。構築の手間=低
   │  ゲート：5本のデータで「当たりテーマが見えたか」を確認
   ▼
【Step2】案B へ拡張（型が見え、月10〜20本へ）
   │  音声をElevenLabs APIで無人化＋画像はステータス自動＋メタ自動
   │  社長：判断3〜5分＋制作20分/本。構築の手間=中
   │  ゲート：粗利率80%維持・1本コストをNotionで監視しながら本数増
   ▼
【Step3】案C 検討（当たり画風・テーマが確定し量産フェーズ）
      画像/編集/投稿をAPI化。承認2ゲートだけ人手
      社長：判断3〜5分/本のみ。構築の手間=高・要投資
      ※着手前に必ず CEO/社長決裁（1件5万円超の支出・新ツール選定・品質基準の確定）
```

**移行の判断ゲート（管理部が監視）**：
- A→B：手動5本＋案A数本で「再生数の当たり筋」が見えたか。見えなければ案Aのまま本数を増やして型探し継続。
- B→C：当たり画風が1つに固定でき、品質を落とさず機械合成できる目処が立ったか。**画像の一貫性が API で担保できない間は C へ進まない**（凡庸量産の回避）。
