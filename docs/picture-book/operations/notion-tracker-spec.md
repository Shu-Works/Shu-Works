## 2. 進行ステータス（主ステータス）の値定義

Make のシナリオ起動キー。順序が遷移フロー。

| 値 | 意味 | 次を起動するシナリオ |
| --- | --- | --- |
| `ネタ確定` | テーマ起票済 | S1（脚本→プロンプト） |
| `プロンプト済` | 脚本＋画像プロンプト完成 | S2（承認依頼A生成） |
| `承認A待ち` | Gmailで承認依頼A送付済、社長返信待ち | （S3が返信を待つ） |
| `物語承認済` | 承認A=GO | S4（画像→音声→動画） |
| `動画生成済` | 動画＋サムネ完成 | S5（承認依頼B生成） |
| `承認B待ち` | Gmailで承認依頼B送付済、社長返信待ち | （S6が返信を待つ） |
| `投稿済` | YouTube投稿完了 | S7（実績取得） |
| `公開中` | 計測フェーズ | S8（分析対象） |
| `要対応` | エラー/詰まり（人手介入） | 管理部アラート |

差し戻し時は対応する前ステータスへ戻す（承認A-NG→`ネタ確定`、承認B-NG→`物語承認済`等）。

## 5. 分析データ設計（30本→上位5本→共通点）

目的：S8 で「何が伸びたか」を構造的に学習し、S0 のテーマ生成にフィードバックする（§31 顧客の声を聞き服従しない＝再生数を聞くが、企画判断は自分で）。

手順：
1. 投稿済 ≥30本になったら「実績ランキング」ビューで **再生数7d 降順 Top5** を機械抽出 → 各行に `トップ5フラグ` ON。
2. Top5 の `テーマ` `確定タイトル`（語彙）`サムネ傾向` `視聴維持率` を ChatGPT が比較。
3. 抽出した共通点を各行の `共通点タグ` に付与し、別ページ「分析メモ」に所見を記録。
4. 所見を S0 のテーマ生成プロンプトに反映（当たりテーマの比率を上げる／外れテーマを `テーマ` から外す）。

分析に効く列（再掲）：`再生数7d`／`視聴維持率`／`登録増`／`いいね率`／`テーマ`／`共通点タグ`／`制作所要分`／`直接費`。
これにより「伸びる本」と「採算に乗る本」を同時に判定できる。
