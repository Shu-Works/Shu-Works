# 承認ゲート設計 — AI 感動絵本チャンネル

**作成日**: 2026-06-17
**目的**: 社長の人手を「2回の判断＋1語返信」に圧縮する。返信1語で次工程が自動で動く。
**送信実体**: Gmail で**下書き（ドラフト）まで自動生成**。送信＝社長確認後（外部送信は CEO 承認後）。

---

## 1. 仕組み（1語で動く設計）

- 各承認依頼メールの**件名にトークン**を埋め込む：`[EP-001][GATE-A]` / `[EP-001][GATE-B]`。
- 社長は**本文に1語だけ**返信：
  - ゲートA：`A-GO`（承認） / `A-NG` （差し戻し。任意で1行理由）
  - ゲートB：`B-GO`（承認・投稿） / `B-NG`（差し戻し。任意で1行理由）
- Make が件名トークンと本文1語を解釈し、Notion の進行ステータスを遷移 → 次シナリオ起動。
- NG 時のみ本文に理由を書けば `差し戻し理由` 列に格納され、再生成に反映。理由なし NG も可（前工程まるごと再走）。

> §6 シンプル：判断ポイントは2つだけ。§27 Three Things：依頼メールも要点3つに絞る。

---

## 2. ゲートA：物語＆タイトル承認依頼（テンプレ）

提示物：確定前のタイトル候補・あらすじ・10シーン要約。**画像生成前**なので、ここで世界観を止められる＝コスト最小で軌道修正できる。

```
宛先: （社長）
件名: [EP-001][GATE-A] 物語＆タイトル承認のお願い／「（タイトル候補）」

社長

第001話の物語とタイトルが固まりました。GOで画像生成に進みます。

━━ Three Things ━━
① タイトル候補：「（タイトル候補）」
② テーマ：（テーマ）
③ あらすじ：（1〜2文）

── 10シーン要約 ──
S1:（…） / S2:（…） / S3:（…） / S4:（…） / S5:（…）
S6:（…） / S7:（…） / S8:（…） / S9:（…） / S10:（…）

脚本全文：（Drive script.md リンク）

━━ ご返信は1語で ━━
　承認 → 「A-GO」
　差し戻し → 「A-NG」（任意で理由を1行）

A-GO で画像10枚・音声・動画化まで自動で進みます。
A-NG なら脚本から作り直します。

― 管理部（自動生成ドラフト）
```

## 3. ゲートB：完成動画＆投稿承認依頼（テンプレ）

提示物：完成動画・サムネ・確定タイトル・説明文・投稿予定枠。**投稿直前の最終ゲート**。

```
宛先: （社長）
件名: [EP-001][GATE-B] 完成動画＆投稿承認のお願い／「（確定タイトル）」

社長

第001話が完成しました。B-GO で予定枠に投稿します。

━━ Three Things ━━
① 完成動画（2〜3分）：（Drive video リンク）
② サムネ：（Drive サムネリンク）
③ 投稿予定枠：（YYYY-MM-DD HH:MM、Calendar枠）

── 投稿メタ情報 ──
タイトル：「（確定タイトル）」
説明文：（説明文ドラフト）
タグ：（タグ）
※冒頭に「この物語はフィクションです。画像・音声はAIで生成しています」表記済み

━━ ご返信は1語で ━━
　承認・投稿 → 「B-GO」
　差し戻し → 「B-NG」（任意で理由を1行：画像/音声/字幕/タイトル 等）

B-GO で Calendar枠を確定し、YouTubeへ投稿します。
B-NG なら該当工程のみ作り直します。

― 管理部（自動生成ドラフト）
```

---

## 4. 返信処理の分岐表

| ゲート | 返信 | Make の処理 | Notion 遷移 |
| --- | --- | --- | --- |
| A | `A-GO` | S4起動 | 進行ステータス→`物語承認済`、承認A=GO |
| A | `A-NG` | 理由を格納しS1再走 | →`ネタ確定`、承認A=NG、差し戻し理由記入 |
| B | `B-GO` | Calendar確定＋YouTube投稿 | →`投稿済`、承認B=GO、YouTube URL記入 |
| B | `B-NG` | 該当工程の再生成 | →`物語承認済`（or 指定工程）、承認B=NG |

---

## 5. 滞留・SLA（管理部の監視責務）

- `承認A待ち` / `承認B待ち` が **48h 超**で社長へリマインド下書きを自動生成。
- 同一エピソードが2回連続NGなら、テーマ自体を `要対応` にして Jobs へエスカレーション（凡庸なネタを量産しない）。
- 承認待ち件数は「承認待ち」ビューで常時可視化。社長が1画面で捌ける状態を保つ。
