# 🎬 チャンネル & SNS 運用センター — Notion 設計書

6チャンネル × 複数SNS媒体の投稿を、1か所で管理するための Notion 構成。

> **たった1つのルール**
> 投稿は必ずここに1行作ってから動く。ここに無い投稿は、この世に存在しない。

---

## 解決する3つのこと

1. **媒体ごとの予約ミスがなくなる** — 1本の動画 × 出す媒体の数だけ「配信」行ができる。カレンダーを見れば、どの媒体にいつ何が出るかが一目でわかる。
2. **投稿済みが行方不明にならない** — 公開したらURLを貼る。過去の投稿が全部ここに残る。
3. **6チャンネルが混ざらない** — チャンネルで色分け・絞り込みができる。

---

## 構造：3つのデータベース

```
📺 チャンネル一覧（6行・マスタ）
      │
      │ リレーション
      ▼
🎞 コンテンツ（企画・制作）　1本の動画 = 1行
      │
      │ リレーション（1対多）
      ▼
📤 配信管理（予約・投稿）　コンテンツ × 媒体 = 1行 ★主役
```

**なぜ2階層に分けるのか。**
1本のショートを YouTube・TikTok・Instagram に出すなら、それは「1つの制作」と「3つの予約」だ。
この2つを1つの表で管理しようとするから、媒体ごとの予約が抜ける。分けた瞬間に抜けなくなる。

---

## 📺 DB1：チャンネル一覧

| プロパティ | 型 | 用途 |
| --- | --- | --- |
| チャンネル名 | タイトル | ①〜⑥ |
| No. | 数値 | 並び順 |
| ジャンル | セレクト | 言霊・スピリチュアル / 歴史・雑学 / 介護・家族 / 物語・朗読 / 占い / 心理学 |
| 運用媒体 | マルチセレクト | このチャンネルで実際に使う媒体だけを入れる |
| コンセプト | テキスト | 1行で言えなければ、まだ決まっていない |
| ターゲット | テキスト | 誰に向けるか |
| 投稿頻度 | テキスト | 例：毎週金曜21:00 |
| 運用ステータス | セレクト | 運用中 / 準備中 / 休止中 |
| チャンネルURL | URL | 各媒体のURLは本文に箇条書き |
| 公開本数 | ロールアップ | 配信管理 →「公開済」件数 |

---

## 🎞 DB2：コンテンツ（企画・制作）

1本の動画・1つのネタ = 1行。**まだ媒体の話はしない。**

| プロパティ | 型 | 用途 |
| --- | --- | --- |
| タイトル | タイトル | 制作上の呼び名 |
| ID | ユニークID（接頭辞 `C`） | C-001 のように自動採番 |
| チャンネル | リレーション → DB1 | 必須 |
| 尺 | セレクト | ショート(〜60秒) / 長尺(10分以上) / 静止画・テキスト |
| 制作ステータス | セレクト | 企画 / 台本 / 素材制作 / 編集 / 完成 / 公開済 / ボツ |
| テーマ・切り口 | テキスト | |
| 台本リンク | URL | |
| 素材リンク | URL | Drive等 |
| 完成予定日 | 日付 | **期限のない仕事は永遠に終わらない** |
| 配信先 | リレーション → DB3 | 自動で紐づく |
| 配信数 | ロールアップ | 何媒体に出したか |
| メモ | テキスト | |

---

## 📤 DB3：配信管理（予約・投稿）★ 毎日見るのはここ

**コンテンツ × 媒体 = 1行。** 3媒体に出すなら3行作る。

| プロパティ | 型 | 用途 |
| --- | --- | --- |
| 投稿名 | タイトル | 例：`【ココ】EP5 ／ YouTube Shorts` |
| チャンネル | リレーション → DB1 | 絞り込み用 |
| コンテンツ | リレーション → DB2 | 元ネタ |
| 媒体 | セレクト | YouTube Shorts / YouTube（長尺）/ TikTok / Instagram リール / Instagram フィード / X / Threads / Facebook / note / LINE VOOM |
| ステータス | セレクト | 未着手 / 素材待ち / **予約待ち** / 予約済 / 公開済 / 取り下げ |
| 予約日時 | 日付（時刻あり） | **必ず時刻まで入れる** |
| ✅予約チェック | チェックボックス | ★ 各SNSの管理画面を**実際に開いて**予約されているのを目で見たらON |
| 公開URL | URL | 公開されたら貼る。ここが埋まって初めて「投稿済み」 |
| キャプション | テキスト | 媒体ごとに文面は変える |
| ハッシュタグ | テキスト | |
| 再生数 / いいね / 保存・シェア | 数値 | 公開1週間後に入れる |
| 振り返り | テキスト | 伸びた理由・伸びなかった理由 |

### ★ 「✅予約チェック」が予約ミスの防波堤

予約ミスは「予約したつもり」で起きる。
Notion上のステータスを「予約済」にするのは*記憶*だが、
チェックボックスは「**管理画面を開いて目で確認した**」という*行為*の記録だ。

- ステータス「予約済」＋チェック **なし** → まだ信用できない
- ステータス「予約済」＋チェック **あり** → 確定

この差だけを見るビュー（下の③）を毎日見る。

---

## ビュー構成（DB3 に作る7つ）

| # | ビュー名 | 種類 | 設定 |
| --- | --- | --- | --- |
| ① | 📅 投稿カレンダー | カレンダー | 予約日時で表示 |
| ② | ⚠️ 予約漏れアラート | テーブル | ステータス =「予約待ち」／予約日時 昇順 |
| ③ | 🔴 予約済み（未確認） | テーブル | ステータス =「予約済」かつ ✅予約チェック = オフ |
| ④ | 🎬 媒体別ボード | ボード | 媒体でグループ化 |
| ⑤ | 📊 進行ボード | ボード | ステータスでグループ化 |
| ⑥ | ✅ 公開済みアーカイブ | テーブル | ステータス =「公開済」／予約日時 降順 |
| ⑦ | 📺 チャンネル別 | テーブル | チャンネルでグループ化 |

**毎朝見るのは ② と ③ の2つだけ。** それ以外は必要なときに開く。

---

## 運用フロー（3ステップ）

```
1. 企画したら   → 🎞 コンテンツ に1行（チャンネルを選ぶ）
2. 媒体を決めたら → 📤 配信管理 に媒体ごとに1行（ステータス＝予約待ち）
3. 各SNSで予約したら → ステータス＝予約済／予約日時を入れる／管理画面を見て ✅予約チェック
                    → 公開されたら 公開URL を貼って 公開済 へ
```

**週1回（金曜）の棚卸し**
- ⚠️ 予約漏れアラート が空になっているか
- 🔴 予約済み（未確認）が空になっているか
- 先週公開分の 再生数 / いいね を入れて 振り返り を1行書く

## Notion へのセットアップ手順

Notion への直接書き込みは、このセッションでは MCP の承認が下りていないため実行できていない。
以下のどちらかで反映する。

### 方法A：CSVインポート（早い）

`docs/sns/import/` の3ファイルを Notion に読み込む。

1. Notion で新規ページ「🎬 チャンネル & SNS 運用センター」を作る
2. `/インポート` → `CSV` → 3ファイルをそれぞれ読み込む
3. **インポート直後は全列がテキストなので、上の表のとおりに型を変える**
   （特に：媒体・ステータス＝セレクト、予約日時＝日付、✅予約チェック＝チェックボックス、
   　チャンネル／コンテンツ＝リレーション）
4. DB3 に上記7つのビューを作る

### 方法B：Claude に作らせる（正確）

Notion MCP の書き込みを承認した上で、こう言う：

> `docs/sns/README.md` の設計どおりに Notion に3つのDBとビューを作って

承認さえ通れば、リレーション・ロールアップ・ビューまで全部自動で作る。
