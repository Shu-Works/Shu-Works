## 2. 取込処理パイプライン（裏側・1顧客あたり）

### Phase 1：受信・整理（Day 0〜1）

| ステップ | やること | ツール | 所要 |
| --- | --- | --- | --- |
| ① ファイル受信 | Drive/LINE/メール からファイル収集 | 各ツール通知 | 即時 |
| ② フォーマット判別 | PDF / Excel / 画像 / 手書き写真 を分類 | 目視 | 5分 |
| ③ ナンバリング | EST-{顧客名}-{連番} で正規化 | スクリプト | 1分 |

### Phase 2：テキスト抽出（Day 1）

| ステップ | やること | ツール | 単価 |
| --- | --- | --- | --- |
| ④ PDF テキスト抽出 | pdfplumber で直接抽出 | Python | ¥0 |
| ⑤ OCR fallback（紙写真） | Document AI（PDFテキストが空の時のみ） | Google Cloud | ¥1/件 |
| ⑥ Excel パース | openpyxl で構造抽出 | Python | ¥0 |

### Phase 3：構造化（Day 1〜2）

抽出したテキストから以下を必ず取り出す：

```
- 顧客名（漢字・ひらがな両方記録）
- 工事名称・施工内容サマリ
- 見積番号（あれば）
- 見積日 / 工期
- 見積金額（税込・税抜・税率を全て記録）
- 施工場所（住所）
- 主要項目の単価リスト
- 担当者名・部署
```

### LLM プロンプト（Claude Haiku 4.5）

```
あなたは見積書から構造化データを抽出するアシスタントです。
以下の見積書テキストから、JSON形式で情報を抽出してください。

【抽出ルール】
- 不明な項目は null とする
- 顧客名は漢字・ひらがな両方記録（ふりがな推測も可）
- 金額は税込・税抜を分けて記録
- 自信度（confidence: 0〜1）も出力

【見積書テキスト】
{抽出済みテキスト}

【出力JSON】
{
  "customer_name_kanji": "...",
  "customer_name_hira": "...",
  "project_name": "...",
  "estimate_no": "...",
  "estimate_date": "YYYY-MM-DD",
  "construction_period_start": "YYYY-MM-DD",
  "construction_period_end": "YYYY-MM-DD",
  "amount_inc_tax": 0,
  "amount_ex_tax": 0,
  "tax_rate": 0.10,
  "location": "...",
  "items": [
    {"name": "...", "unit_price": 0, "quantity": 0, "subtotal": 0}
  ],
  "contact_person": "...",
  "confidence": 0.95
}
```

### Phase 4：QA（Day 2）

- AI confidence ≥ 0.90：**自動承認**（人間チェック不要）
- AI confidence 0.80〜0.89：**スポットチェック**（金額・顧客名のみ目視確認・1件30秒）
- AI confidence < 0.80：**全項目目視確認**（1件 2分）

最初の5社では、**全件スポットチェック**を実施し、AI 精度の測定データを取る。

### Phase 5：Embedding・DB登録（Day 2〜3）

```python
# 簡素化したフロー
for estimate in extracted_estimates:
    # ベクトル化（検索用）
    embedding = openai.embeddings.create(
        model="text-embedding-3-small",
        input=f"{estimate.customer_name_kanji} {estimate.project_name} {estimate.items_summary}"
    )
    
    # Supabase pgvector に登録
    supabase.table("estimates").insert({
        "tenant_id": tenant_id,
        "structured_data": estimate.dict(),
        "embedding": embedding,
        "raw_text": estimate.raw_text,
        "file_url": estimate.file_url,
    }).execute()
```

## 3. やっかいなケースの対応マトリックス

| ケース | 対応 |
| --- | --- |
| 手書きの見積書 | OCR後、必ず全項目目視確認。最初の5社は CEO に再確認依頼 |
| 写真がブレてる/暗い | LINEで自動返信「もう一度撮り直してお送りいただけますか？」 |
| 同一顧客の複数バージョン（見積→修正→確定） | AIで判別、最新版を「primary」、それ以外を「revision」とフラグ |
| 顧客名のゆらぎ（山田／山田様／山田健一） | 工務店ごとに **表記揺れ正規化テーブル** を作成 |
| 金額が税込/税別の表記が不明 | 両方の可能性を併記、検索結果には警告を表示 |
| 個人情報を含むファイル名 | アップ後即時にUUID化、元ファイル名はメタデータに保管 |
| 重複アップロード | ファイルハッシュで判別、自動スキップ |
| 200件超のアップロード | 「直近2〜3年分」を優先取込、残りは「アーカイブ」として保管（検索対象外） |

## 7. リスク・例外対応

| リスク | 対策 |
| --- | --- |
| 顧客が大量のファイルを一気にアップ → サーバ落ち | Cloudflare Workers のレート制限で吸収、キューイング |
| 個人情報漏洩 | 暗号化保管・アクセスログ1年保管・データはテナント分離 |
| OCR 誤読で金額ミス | 全件 confidence 表示、低い場合は顧客にも確認依頼 |
| 顧客が「全件届いてない」と苦情 | ハッシュベースの重複検知 + 受信ログ全件保管 |
| 解約時のデータ返却 | CSV エクスポート機能を完了通知メール内に同梱予定 |
